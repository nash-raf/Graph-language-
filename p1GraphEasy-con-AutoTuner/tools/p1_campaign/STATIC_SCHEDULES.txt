Effect-derived static schedules (2026-10-20)

The first supported family is ordered source preparation, independent
destination-owner work, and joined completion. The compiler's normal spatial
analysis supplies the ownership, immutable-domain and alias/effect certificate.
A late pass separately rejects callback context observers, opaque calls,
volatile/atomic operations and unsupported lifecycle behavior. It emits a
constant symbolic plan and a named LLVM proof record. Owner cardinality stays
dynamic. This is schedule lowering; it introduces no new dependency discharge,
floating-point reassociation, frontier deduplication or algorithm replacement.

The runtime checks descriptor version, callback identities, capabilities and
current ownership before executing the same source coverage in native order,
then the existing owner worker team and join. It preserves the preparation
grant and restores the caller's budget. Unmatched invocations retain generic
DAG scheduling. Execution ABI version 4 requires a coordinated rebuild.

Controls:
  SGPL_NO_STATIC_SCHEDULE_LOWERING=1  omit compiler-generated plans
  SGPL_NO_STATIC_SCHEDULE=1           retain generic scheduling, same binary
  SGPL_STATIC_SCHEDULE_STATS=1        compiler activation/refusal diagnostics
  SGPL_STATIC_SCHEDULE_DEBUG=1        diagnostic runtime activation (not timing)

This implementation does not yet lower arbitrary partial DAGs, perform general
transitive reduction, or fuse arbitrary callback chains. Existing ownership,
snapshot and privatization proofs remain authoritative. Unknown obligations
are not removed. The change is independent of full-graph kernel lowering.

Regression follow-up (2026-10-20):
  report_static_regression_causes.py RESULTS_ROOT
  C:\p1-static-schedules-20261020\regression_cause_report.html
The large Luxembourg CC causal chain is established: the universal context
growth moved the cached preparation cursors from offset0 to offset16 modulo64.
Eight partition counters form a 64-byte row. Adjacent rows belong to different
workers, so a misaligned base makes their independent counters share a line.
The extra cost is in counting/filling, with unchanged graph work and rounds.
Inverse controls reproduce the penalty in the old build; aligning cursors
recovers the candidate while retaining the new context and static schedule.

Three serial Kaggle studies preserve 14,080 component timings, 3,600 native
alignment timings, and 675 same-binary instrumented observations. The last
study holds code addresses fixed and changes only cursor/record offsets.
Cursor offset 16 adds 6.8% BFS, 8.2% SSSP and 16.7% CC time in those diagnostics;
record-only offset controls do not reproduce the effect. A/A controls pass.
One-worker observations show no corresponding large penalty. Instrumented
results are diagnostic only and cannot promote a production repair.

Attribution remains incomplete for some original cases. Seven of 16 flags pass
strict independent two-block component re-confirmation on the follow-up VM.
In particular, both original SSSP wing cursor probes have offset 48, so cursor
movement alone does not explain their complete original relative difference.
The report retains these limits and every original flag. Hardware cycles were
denied on Kaggle; logical shared-line writes are not hardware HITM counts.

The general repair is aligned, cache-line-padded chunk cursor rows, with the
padded stride used consistently by count/fill/prefix operations. No production
repair was promoted or full 244-case repair benchmark claimed in this follow-up.
All original static-schedule implementation changes remain in place.

Preparation now obtains a 64-byte-aligned view of its leased cursor allocation
and rounds each chunk's counter row to whole cache lines. The logical partition
count, source/edge occurrence order, weight lookup, effects and DAG are unchanged.
Only the private preparation descriptor gains a stride; the public execution
context ABI does not change. SGPL_PREP_CACHE_LINE_BYTES can target larger lines.
The lease retains the original allocation for freeing, capacity accounting and
failure recovery, including the uncached path. SGPL_NO_CURSOR_ALIGNMENT=1 is a
same-binary dense-row control; it does not disable static schedules.
