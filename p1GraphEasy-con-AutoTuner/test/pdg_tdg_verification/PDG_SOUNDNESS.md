# PDG soundness: proof boundary and current result

**Status: partial.** `PDGEdgeCoverage.tla` proves the edge-construction rule for an arbitrary ordered pair of dynamic events, conditional on the explicitly listed coverage assumptions. It does **not** prove that every LLVM instruction, every SGPL runtime call, the loop-carrier classifier, or the TDG projection satisfies those assumptions. Consequently this is not yet an end-to-end PDG or scheduler soundness proof.

## Property

Within one invocation of a valid LLVM function, let `event(x)` denote an executed instance of static instruction `x`. A static PDG is dependence-sound if each pair of potentially ordered dynamic events that (1) reads and writes overlapping program bytes, (2) includes an opaque observable effect, (3) has a true SSA data dependence, or (4) has a true control dependence, projects to a PDG edge. When both events project to one static instruction, the edge is a self-edge. Extra edges are allowed. This is an **edge coverage** property; it does not by itself justify moving, extracting, or running tasks.

## Implementation argument

| Obligation | Implemented rule | Why it covers the case | Remaining trust |
|---|---|---|---|
| Explicit reads/writes | `buildGraph` records every ordinary `LoadInst`/`StoreInst` and adds `MEM_MAY` for every potentially ordered pair with a write unless disjointness is proved. Loop-local stores get `WAW_LOOP_MAY` self-edges. | A concrete conflicting pair cannot be omitted if reachability and disjointness answers are conservative. | LLVM `isPotentiallyReachable` and `AAResults` contracts on valid IR; the event-to-instruction projection. |
| Cross-iteration aliasing | If two accesses share any containing loop, the pair bypasses `AA.NoAlias` and is sent to `DependenceInfo`. | A same-iteration alias answer cannot erase a possible dependence between different iterations. | Correct `LoopInfo` after the pre-PDG transformations; justify any `NoAlias` decision for accesses in different loop regions. |
| Opaque effects | All remaining `CallBase` instructions and all other memory instructions outside ordinary loads/stores/allocas are barriers. Each barrier connects to every potentially ordered instruction; a loop-local barrier gets a self-edge. | There is no reliance on `argmemonly` to omit a memory edge. | A call or instruction whose effects are absent from LLVM IR must be represented by the caller's contract; inline assembly and indirect calls remain barriers. |
| SSA values | Every instruction connects to its instruction users; PHI incoming values are also connected. | A value cannot be used before its defining instruction without an edge. | LLVM SSA validity, and no unmodelled interprocedural value flow. |
| Control | `CTRL_MAY` connects every conditional terminator to a reachable instruction that does not postdominate it, and to reachable PHIs at joins. | This overapproximates ordinary termination-insensitive branch/switch control dependence and PHI predecessor selection. | CFG/postdominator semantics for exceptional and nonterminating paths; proof of the exact dynamic control-dependence definition. |

The pass now expands `llvm.memset`, `llvm.memcpy`, and lowerable `llvm.memmove` with LLVM's intrinsic-lowering routines **after CleanCut and before PDG**, exposing their loads and stores. A corpus scan of 237 `.graph` fixtures found `llvm.memset` in 95 and `llvm.memcpy` in two graph-comprehension fixtures. The one compilation that timed out had already produced its pre-PDG dump; that dump contained no additional argument-memory-only call. No other such call was observed in this CPU-backend corpus. The `autograph_neighbor_iter_init/next` declarations were **not** marked `argmemonly`. Their layout, restart, and profiling behavior is not hand-inlined; they remain conservative call barriers. Unsupported memory intrinsics also remain barriers.

Later LLVM optimization can recognize an expanded byte-copy loop and emit `llvm.memcpy` again for machine-code generation. PDG analyzes the expanded form before that later optimization.

The TLA+ theorem is intentionally small: for an arbitrary event pair, `ActualBefore => MayReach`, `ActualAlias => PotentialAlias`, `ActualControl => MayControl`, and `ActualSSA => DefUse` imply `ActualDependence => PDGEdge`. The self-edge case additionally assumes that two executions of one static instruction in an invocation occur inside a loop. These are premises to discharge against the compiler and LLVM, not conclusions produced by TLA+.

## Loop parallelism is a separate obligation

`analyzeAndAnnotateLoop` uses `DependenceInfo`, distance classification, PHI recognition, and call-effect screening to choose sequential, DOALL, or DOACROSS behavior. An edge-complete PDG does not establish that this *classification* is sound. This change makes volatile/atomic loads and stores, fences, and other unmodelled memory instructions force an unknown-carrier verdict, and removes environment switches that restored previously known unsafe verdicts. A `LoopAccessAnalysis` result of `NoOpinion` still permits the classifier's DOALL verdict, so that gate is not a complete proof. A full proof still needs to show, for every emitted parallel loop, that every carried dependence is either absent or synchronized at the right distance. In particular, the `isLoopIndependent`, zero-distance, and scalar-PHI paths need independent review against LLVM's `DependenceInfo` specification and the outliner's emitted synchronization.

Likewise, TDG task safety requires that the vertex-to-task projection retain all non-barrier edges, that any removed call-barrier edge is covered by a sound whole-task effect summary, and that extraction, capture, hoisting, and runtime scheduling preserve the resulting order. The existing `TDGTaskSafetyProof.tla` proves the abstract scheduler only when those summaries and required-order relations are sound. Neither formal artifact yet establishes those implementation premises.

## Evidence and next proof steps

The compiler build and shared graph/ordinary TDG regression check IR validity, serial-reference outputs, dependent ordering, actual independent overlap, and thread-budget behavior. PDG-input dumps confirm that the checked `llvm.memset` and `llvm.memcpy` calls became explicit loads/stores. The graph-comprehension output matches the serial reference after the graph literal's previously uninitialized weight pointer was fixed. These are regression evidence, not universal proof.

To close the proof, specify the accepted LLVM IR subset and SGPL observable semantics, then discharge three implementation lemmas: (1) every actual effect maps to an explicit load/store or barrier, including runtime and GPU calls; (2) the loop-carrier verdict and generated DOACROSS synchronization preserve every loop-carried dependence; and (3) task coarsening, edge removal, and hoisting preserve all required order edges. A proof of these lemmas, together with the pairwise edge theorem, would support the claimed PDG-to-TDG safety result. Graph-task sharing is now enabled by default, but that does not discharge these proof obligations.
